## Validation and failures

Detailed local search, recipe candidates, byte inventory, image metadata/export and helper/static logs are under `.local/m7-dsmlp-audit-v1/`. The compact machine packet is `docs/reviews/M7.dsmlp-readiness.validation.json` (private generated evidence).

Tests were written and observed failing before helper/guard implementation. Static checks initially found a Mac typing stub issue for Linux `sched_getaffinity` and a missing protocol declaration for dense search. Both were corrected without changing runtime/model behavior.

Fresh review identified a supervisor-signal gap: default SIGTERM/SIGHUP could bypass cleanup of its detached worker. The revised harness translates termination signals into bounded cleanup, kills owned process-group descendants even if the root has exited, and binds Linux worker parent-death behavior before model imports. Local regression checks use sleeping Python subprocesses, never actual models or cluster jobs. Repeated signals don't interrupt bounded cleanup. A forced SIGKILL of the entire Kubernetes pod remains a scheduler event. Preserve its status/evidence.

All prepared evidence is new and separately named. The image was exported, not rebuilt or pushed. Existing M7 test evidence and the model's original hashes are retained. A metadata-only local container probe read Python/package/source information. It performed no inference or fitting.

## Failure modes and pending decisions

- Missing original recipe: blocked metadata preflight. Request the genuine record. Don't infer an original from `pip freeze` or the old M4 recipe.
- Different kernel/glibc/platform: strict digest/runtime failure. The same image doesn't virtualize the host kernel. Stop before real startup.
- Image unavailable to Kubernetes: don't submit a guessed registry reference. Obtain an approved unchanged-image import mechanism. No private/public push is authorized.
- Wrong UID/private mount or incomplete transfer: stop on permissions/hash mismatch, preserve the directory and correct the approved transfer scope. Never overwrite originals.
- Resource breach, timeout or supervisor interruption: stop owned workers, preserve partial cases/logs and return failure. Sampling limitations are explicit. High-water RSS is checked too.
- Successful lexical/import/model-load check: retain it as evidence but keep full real-model HTTP parity open.

The username/workspace, persistent host/container path mapping, approved offline image route and concrete pod/execution manifest need user confirmation before submission. The 300-second smoke excludes separately recorded transport/provisioning and metadata-only preflight, but includes every component loader check, model startup, HTTP requests and shutdown. No timer reset within a failed smoke is allowed.

## Interview and human-understanding checks

1. Why can the same image fail a query-recipe digest? The rootfs stays fixed while the kernel comes from the host. Explain which platform/runtime fields enter this project's digest.
2. Why can't a copied tar file be used directly with `launch.sh -i`? Kubernetes needs an accessible image reference or approved runtime-cache import. Distinguish archive SHA, platform manifest and configuration digest.
3. Why is host `MemAvailable` insufficient inside a container? The pod's cgroup headroom may be smaller. Trace the effective minimum and distinguish 32 GB allocation from the 12 GiB application ceiling.
4. What does real HTTP parity establish? Equal ordered native inputs and predictions on declared cases in one pinned runtime, not relevance improvement, production throughput or recovered historical training provenance.
5. Why monitor the worker group rather than only its PID? Descendants can outlive the root. Explain signal handling, parent-death binding, shutdown reserve and preserved failure output.

Generated outlines and a fresh code review don't establish human understanding or milestone acceptance. The lead should inspect a recipe mismatch report, the pod dry-run image/mount/resource fields, one post-DMatrix capture pair and the supervisor's failed-run cleanup before authorizing execution.
