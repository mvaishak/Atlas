## Data flow, alternatives and failure handling

The added inventory reads frozen review pins, validates manifest/completion identities,
streams artifact bytes through SHA-256 and writes a fresh diagnostic JSON. It imports
only the Python standard library. It cannot authorize a fit, even when every byte check
passes. The existing offline evaluator, feature context, HTTP route and native adapter
remain unchanged. The intended experiment uses those existing boundaries after a
compatible Linux runtime passes the real-data gates.

| Alternative | Decision |
| --- | --- |
| Reuse the connected synthetic-only Linux virtualenv | Rejected for real encoding: 5 required distributions are absent |
| Repair the Mac native stack or build a new container environment | Rejected under the explicit environment restrictions |
| Substitute the small pilot bundle or trust historical hash strings | Rejected; the original full M4 bundle was found and freshly hashed |
| Keep a source-only prerequisite package and stop before fitting | Chosen under the user's unavailable-runtime fallback |

Changed or missing bytes, substituted identities and symlink files produce failed
checks. Existing output directories are refused. The inventory's exit code 2 records
remaining gates even when the byte checks pass. Its training flag is always false.
Runtime/library compatibility, semantic alignment and actual prediction parity need
their own evidence; hashes don't establish those properties.

## Understanding and development log

1. What does a hash establish? Byte identity with a recorded source; it doesn't prove
   vector normalization, compatible native execution or feature parity.
2. Why can't the native 42-case pass authorize training? It uses synthetic features
   and a zero-update model; real encoder execution and objective updates are separate.
3. Why must missing retrieval scores fail? A genuine BM25 zero is computed from the
   scorer. Absence from top-100 gives no score for a judged candidate.
4. Why must fixed-pool Recall@100 stay constant? Permuting the same 100 identities
   preserves the known-exact positives contained in the pool.
5. What prevents development leakage? Preserve normalized training group boundaries,
   fit only the complete judged training groups and keep development solely for reporting.
