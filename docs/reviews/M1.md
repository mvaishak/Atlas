## Scope and architecture

M1 adds a `src/atlasrank` package, a small local tracking-check command, fixture tests, Ruff, strict mypy, a Python/dependency specification, a Mac/Linux CI definition, and an environment audit. It adds no retrieval, metric implementation, sampler, model, data pipeline, or API.

The command explicitly creates an MLflow client pointing to a local SQLite file. A synthetic run stores an M1 parameter, a clearly named fixture metric, and a JSON artifact. A fresh client reopens the run and verifies an exported artifact byte-for-byte; an export record includes its SHA-256. Each invocation creates a separate run. No MLflow server is needed.

Package import and CLI help don't import MLflow or PyTorch and don't create storage. The tracking operation imports MLflow only when invoked. Tests also check that an inherited remote tracking URI cannot redirect this local check.

## Capacity estimates and proposed limits

For a float32 384-dimensional flat index, vector storage is `N * 384 * 4` bytes. These are calculated scenarios, not observed catalog sizes or benchmarks.

| Indexed products | Vectors alone, GiB |
| --- | ---: |
| 100,000 | 0.143 |
| 500,000 | 0.715 |
| 1,000,000 | 1.431 |
| 2,000,000 | 2.861 |

A separate embedding matrix and a copied FAISS index can double this component. Retaining both pretrained and fine-tuned embeddings/indexes on disk can require four times one vector payload. Product strings, BM25 sparse structures, Python objects, encoder weights, batches, caches, and temporary files add unknown overhead. [FAISS index storage](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes).

Propose a single-bundle serving process ceiling of 6 GiB RSS, an 8 GiB preprocessing peak, and a 30 GiB local data/artifact reservation, leaving memory/disk for the OS and temporary work. These are proposed budgets for the lead's M2 review, not enforced limits or proof that the full US corpus fits. M2 must measure actual product counts and metadata/lexical sizes before full indexing; stop for approval if the scope doesn't fit. No corpus was downloaded to estimate these values.

## Failure modes and remaining checks

- Missing or incompatible dependencies can prevent the tracking command from importing. Locked macOS sync, dependency checks, and real tracking checks passed. Lead review of the lock and actual Linux runtime/CI checks remain acceptance gates; universal resolution alone doesn't establish Linux execution.
- SQLite metadata and artifact files are separate persistence paths. The fresh-client and byte-equality tests detect incomplete writes/exports. This smoke command assumes single-user sequential setup; it isn't a concurrent production tracker.
- Reusing a database after future schema upgrades may require an explicit migration plan. Preserve experiment history; don't delete it to make a check pass. Routine tests use isolated temporary roots.
- Platform wheel availability doesn't establish NumPy/OpenMP/FAISS runtime compatibility. Run the actual platform imports in the owning milestones and preserve CPU reference behavior.
- No datasets or trained encoders exist, so memory estimates and future metric/sampling tests are unexecuted. M2 must check XGBoost linear-gain NDCG without fitting and define supervision fixtures; M5 must test the real sampler/loss before Colab.

## Technical interview questions and answer outlines

1. **What do `pyproject.toml`, `uv.lock`, and a wheel each guarantee?** The project declares requirements/build configuration; the lock fixes the resolved dependency graph and artifacts; the wheel packages application code. A wheel built with `--no-deps` doesn't validate runtime dependencies.
2. **Why reopen an MLflow run with a fresh client and verify artifact bytes?** Metadata persistence and artifact persistence can fail independently. Reopening and comparing exported content tests the stored result rather than an in-memory success response.
3. **Why do E/S/C/I gains 100/10/1/0 match 1/0.1/0.01/0 under linear NDCG?** Scaling numerator and ideal denominator equally cancels. Exponential gain breaks that relation; zero-IDCG behavior must follow the project's explicit contract.
4. **Why isn't a product judged I for another query a safe negative here?** Relevance is query-specific. Only this training query's judged I is admissible; unknown pairs, held-out groups, S/C, and known E products must be excluded or masked according to the contract.
5. **Why doesn't a 1.43 GiB vector estimate establish that a million-product system fits in RAM?** It excludes duplicate buffers, lexical indexes, metadata objects, model weights, batches, and OS needs. Actual peak measurements must precede scope and optimization decisions.
